# assets/loader —— 四个模组加载器的标志

这里是 `ui/VersionIcons.cpp::loaderMark()` 画的四个加载器的**真图**。用户 2026-09-28：
「把模组加载器的贴图换了」；再往前 2026-09-26 那句是「使用实际的那几个 mc 草块 / fabric
布料等的图片文件，不用担心侵权问题」—— 所以这四个不再是照着品牌色**自己画**的简化图形，
而是各家自己的图（那几个方块仍然是画的，见 `VersionIcons.hpp` 里那段说明）。

四张都是 **64 × 64** 的成品图（底色、圆角、留白都已经烤进去了）：界面那边只做等比缩放，
不再往上叠底色。之所以烤进来而不是运行时拼，是因为**最终长什么样在生成这一步就看得见**
（拼法见下面各自那一行），运行时那段代码因此只剩"读一张图、缩到要的边长"。

> ★ **2026-09-29：`fabric.png` 那块 `#38342A` 的圆角底去掉了**（下面那一行已经改写）。
> 用户原话「fabric的图标黑色部分改成透明的」。**另外三张一个字节都没动** —— 它们各自的
> 底色是那个标志的一部分（Forge 的橙底、NeoForge 的深底），只剩 Fabric 这张的底色是"垫上
> 去的"。于是现在四张里只有 Fabric 是**透明底 + 一块浅色叶子**，在浅色背景（列表、实例行）
> 上比另外三张淡一档 —— 这是那条要求的直接结果，不是画错了。

## `fabric.png` 那块底是怎么抠的（2026-09-29）

底是**烤进去的**、图上没有 alpha 分界，所以抠不出一张"现成的蒙版"，只能按**离底色的远近**
现算一份 —— 走的还是上面那个"生成这一步做掉、运行时只缩放"的路子，只是这回生成的是**一张
新图**而不是一个拼法：

1. 底色取 `(56, 52, 42)`（就是原来那块 `#38342A`）；
2. 每个像素到它的**切比雪夫距离** `d = max(|ΔR|, |ΔG|, |ΔB|)`；
3. `d ≤ 6` 判成底 ⇒ 全透明；`d ≥ 30` 判成叶子 ⇒ 原样不透明；中间那一段线性拉成 alpha
   （叶子的边缘是抗锯齿过的，硬切会留一圈锯齿）；
4. 半透明的那些像素再做一遍**反合成**（先按 alpha 把底色减回去，再按新 alpha 归一化），
   否则叶子边缘会带着一层深色的"脏边"——那圈脏边在浅色背景上比叶子本身还显眼。

这样做的前提是**叶子里一个深色像素都没有**（那些深色全是那块底，叶子自己只在织物纹理上
有一点深浅）：抠之前先按 ASCII 图看过一遍，确实如此。要是哪天换了张带深色描边的叶子，
第 3 步那条 `d ≥ 30 判成叶子` 就会把描边一起吃掉 —— 那时候得改成按连通区域认。

**另外三张不要照这个做**：Forge 的橙底、NeoForge 的深底都是那个标志自己的底色，抠掉以后
铁砧和狐狸会掉在透明底上、对比度反而更低。

**侵权**：这四张是各家的标志，用户明确说「不用担心侵权问题」。要换成别的图：直接盖掉
同名文件就行，键（`fabric` / `forge` / `neoforge` / `optifine`）和
`VersionIcons::iconCandidateKeys()` 一个字都不用改 —— 那几个键**已经写进了实例的
`wtfml.meta`**（是稳定身份，见 `VersionIcons.hpp`）。
