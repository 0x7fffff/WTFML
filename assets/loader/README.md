# assets/loader —— 四个模组加载器的标志

这里是 `ui/VersionIcons.cpp::loaderMark()` 画的四个加载器的**真图**。用户 2026-09-28：
「把模组加载器的贴图换了」；再往前 2026-09-26 那句是「使用实际的那几个 mc 草块 / fabric
布料等的图片文件，不用担心侵权问题」—— 所以这四个不再是照着品牌色**自己画**的简化图形，
而是各家自己的图（那几个方块仍然是画的，见 `VersionIcons.hpp` 里那段说明）。

四张都是 **64 × 64** 的成品图（底色、圆角、留白都已经烤进去了）：界面那边只做等比缩放，
不再往上叠底色。之所以烤进来而不是运行时拼，是因为**最终长什么样在生成这一步就看得见**
（拼法见下面各自那一行），运行时那段代码因此只剩"读一张图、缩到要的边长"。

> ★ **2026-09-29（第二轮）：fabric / forge 换成了用户给的新图，这两张现在是透明底。**
> 用户原话「把fabric的图标换成 D:\downloads 里的那个 logo.png，forge 用［那张铁砧的图］，

> **自带透明底和一圈深色描边**，抠底这件事整个作废（下面那段抠法只剩史料价值，见文末）。
>

## `forge.png` 那张白底是怎么抠的（2026-09-29）

和上午抠 Fabric 那块圆角底一个路数（图上没有 alpha 分界 ⇒ 蒙版只能现算），但判据不一样：
那张的"底"是**白**，所以要按**离白有多远**拉 alpha，而不是"离某个底色有多近"：

1. `d = 255 - min(R, G, B)` —— 纯白 ⇒ 0，铁砧那个藏青 `(30,45,67)` ⇒ 225。
   用 `min` 而不是"离 255,255,255 的三维距离"是为了**对偏色不敏感**：这张是从 JPEG 来的，
   背景上有一堆 `253,255,255` / `255,254,255` 这种压缩噪点，按三维距离算它们会半透明地
   留在图上（在深色主题下就是一片脏）。
2. 先扫一遍取 `dmax`（这张是 **252**），然后 `alpha = 255 * d / dmax`；`d ≤ 3` 直接判 0。
3. 半透明那圈再**反合成**（`F = (C - (1-a)*255) / a`，减的是白）—— 不做这一步，铁砧边上
   会留一圈发白的边，在白底列表里看不出来、在选中行那层浅灰底上就显形了。

**这一招只对"白底 + 深色标志"成立。** NeoForge 那张的灰底**不要**照做：那是官方图自带的
底，抠掉以后橘色狐狸会掉在透明底上，白耳朵和透明的对比度反而更低。

## 附录：上午那版 Fabric 是怎么抠的（**已作废**，留着看形状）

用户 2026-09-29 上午说的「fabric的图标黑色部分改成透明的」指的是**旧的**那张 —— 官方
`icon.png` 缩到 78% 之后再垫一块 `#38342A` 的圆角底、底色是**烤进 PNG** 的。当时的抠法是
按**离底色的切比雪夫距离** `d = max(|ΔR|,|ΔG|,|ΔB|)` 分三档（`d ≤ 6` 全透明 / `d ≥ 30` 原样 /
中间线性拉 alpha），半透明那圈再反合成一遍。前提是"叶子里一个深色像素都没有"，抠之前按
ASCII 图核过确实如此。

**现在不需要了**：用户当天下午换的那张 `logo.png` 本来就是透明底，而且叶子的深色描边是
**标志自己的一部分**（抠掉叶子就散在背景上了）。这一段留着是因为"烤进去的底怎么按颜色
距离还原成 alpha"这个手法以后还可能用到 —— 比如哪天有人又拿来一张带底的图。

**侵权**：这四张是各家的标志，用户明确说「不用担心侵权问题」。要换成别的图：直接盖掉
同名文件就行，键（`fabric` / `forge` / `neoforge` / `optifine`）和
`VersionIcons::iconCandidateKeys()` 一个字都不用改 —— 那几个键**已经写进了实例的
`wtfml.meta`**（是稳定身份，见 `VersionIcons.hpp`）。
