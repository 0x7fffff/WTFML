# 实例预设：当前使用方式与边界

预设用于用户明确确认的初始化，不在后续启动时自动恢复配置或补回被删的模组。

## 创建与使用

1. 在「管理 → 预设」按类别新建。当前每类独立：游戏设置、模组、资源包、数据包。
2. 游戏设置点击「编辑游戏设置与按键」，可添加视角、界面尺寸、自动跳跃、渲染距离和按键。
   也可以从已有实例提取；其它服务器、MaLiLib 与配置文件段保留原有提取/应用能力。
3. 模组点击「编辑模组清单」，填写 Modrinth / CurseForge 稳定项目 ID，设置必要/可选。
   限定版本/加载器留空表示跟随目标实例；不匹配时不会下载其它游戏版本来凑数。
4. 下载游戏时，在 OptiFine 下的「预设」行按类别选择。先完成游戏及加载器，再处理预设；
   模组步骤继续属于原安装任务，可从任务中心取消。基础实例装好但预设失败会保留实例并说明部分应用。
5. 也可在预设管理中选目标实例，先预览再应用。平台模组的具体发行文件在执行时联网解析。

资源包/光影继续从已有实例提取；数据包按世界处理，没有目标世界时保留为待应用，不创建世界。
默认项和旧混合预设保持旧数据，不自动迁移为四类默认组合。首版仍按现有每类单选。

## 模组执行保护

- 复用资源平台取数与生产下载器；顺序查询并去重，必要前置最多 256 个项目，整项最长 600 秒。
- 平台明确没有发行版与网络未知分开；必要项未解决时不写入模组。
- 必要文件全部通过大小/SHA-1 检查后才进入写入阶段；不接受无可信 SHA-1 的远端模组。
- 文件名只接受安全 JAR 基名，拒绝路径穿越、危险目录链接和同名内容冲突；已有文件不覆盖。
- 可选依赖失败时保守跳过可选下载项，不留下已知缺前置的可选模组。
- 精确依赖按平台发行列表里的版本 ID 筛选；互斥约束和缺少项目 ID 的版本专属依赖安全阻止。
  复杂依赖求解、全量已安装模组身份/冲突识别、候选替代确认和详细下载前确认仍需补齐。
  中途写盘错误会如实报告已写入数量，不声称全量回滚。
- 执行记录原子保存到实例的 `wtfml.preset-mod-install.json`，包含版本/加载器、所选预设内容快照、
  计划文件身份、成功/取消/部分失败状态；`plannedFiles` 只是计划，不代表每项均已落盘。

## 模组管理按钮原设计

原稿在仓库上一级 `其余的一些设计.md` 的「Mod 操作 / 批量操作规则」：
选中模组出现 Action Panel；包括启用、禁用、更新、删除、打开目录、详情、配置管理。
混合选择启用/禁用模组时，按原稿隐藏启用/禁用，仅保留无歧义的批量操作。
本轮只定位并记录此计划，未擅自修改模组管理页面的布局。

2026-10-18 用户补充示意图：采用「实例导航 / 宽模组列表 / 窄操作栏」版型，
左侧沿用现有实例导航，不照搬示意图。右侧建议宽 240–280 逻辑像素，不反向撑高/撑宽窗口；
无选择时收起或显示简短提示，清除选择与关闭操作栏的行为应明确区分。
列表上方保留添加、搜索/排序、全部/已启用/已禁用/需要处理及全选/反选/清除。
选中行保持主题浅底，行内显示名称、版本、实际启用状态和有依据的兼容/问题标记，
未知不能伪装成兼容。右栏按状态控制、版本管理、实例迁移、删除、更多分组。
同日补充原始对话后，以原稿后段为准，旧 MD 的“混合选择隐藏状态操作”已过时：

- 未选择时面板收起；选中后从右侧滑入，不做遮挡列表的悬浮菜单，也不全局常驻。
- 固定位置的状态下拉提供「全部启用 / 全部禁用 / 逐项反转」；反转明确指每项独立翻转，
  不是按第一项状态决定整批动作。操作前展示已启用/已禁用数量。
- 全选/反选/清除属于列表顶部的选择工具，不放右栏。
- 高频主操作为状态、检查更新、复制到实例、删除；实际更新放后续确认，移动比复制有更高风险。
- 标题显示已选择数量；成功后收起、失败保留是对话中的建议，具体是否清空选择仍应结合操作定义。
- 更多容纳详情、文件位置、依赖/冲突、网页、导出列表；只在有能力时显示，不把未知伪装成检查成功。
- 删除需确认；“同时删除配置”仅是原稿建议，默认不勾选，配置归属不明确时不提供破坏性操作。
- 固定面板、自动整理/清残留、测试实例/启动验证属于助手提出的扩展建议，并非已确认首版要求。
- 共用可选 `ContextActionPanel` 容器，但不强制所有页面三栏化；存档、服务器、资源包未来按需接入。

用户随后已接受交互修正：保留成功后的选择、× 仅收起、清除选择放列表顶部、反转移入更多、
删除不附带清配置。最终实现以 [MOD_ACTION_PANEL.md](MOD_ACTION_PANEL.md) 为准，上面的对话整理保留作历史来源。
