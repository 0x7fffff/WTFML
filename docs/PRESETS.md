## 创建与使用

1. 在「管理 → 预设」按类别新建。当前每类独立：游戏设置、模组、资源包、数据包。
2. 游戏设置点击「编辑游戏设置与按键」，可添加视角、界面尺寸、自动跳跃、渲染距离和按键。
   视角用角度编辑（内部仍保存原版归一化数值），界面尺寸显示“自动”，自动跳跃选择开/关。
   也可以从已有实例提取；其它服务器、MaLiLib 与配置文件段保留原有提取/应用能力。
3. 模组点击「编辑模组清单」，可直接粘贴 Modrinth 模组网页链接添加，或填写项目 ID，设置必要/可选。
   重复添加会定位原行；CurseForge 仍需数字项目 ID，网页 slug 不能当作稳定 ID。
   限定版本/加载器留空表示跟随目标实例；不匹配时不会下载其它游戏版本来凑数。
4. 下载游戏时，在 OptiFine 下的「预设」行按类别选择。先完成游戏及加载器，再处理预设；
   模组步骤继续属于原安装任务，可从任务中心取消。基础实例装好但预设失败会保留实例并说明部分应用。
5. 也可在预设管理中选目标实例，先预览再应用。平台模组的具体发行文件在执行时联网解析。

资源包/光影继续从已有实例提取；数据包按世界处理，没有目标世界时保留为待应用，不创建世界。
数据包换掉同名那一份时先拷到旁边的暂存、再两段改名换过去。每一步之前先在目标旁边落一份登记
`.wtfml-txn-<目标标记>.json`；进程被杀掉后，下一次碰到这个目录（采集或应用）会按登记把那一趟
收尾：目标还没换走就收掉暂存；目标已经挪走就把原件放回原位；新内容已经发布就收掉旧的那一份。
登记读不懂、或者残骸没有登记 ⇒ 一个字节都不动，保留全部现场并提示人工检查，不凭文件名前缀
删除或自动归位。换包期间实例目录锁与「游戏在跑就不动手」的检查仍由应用入口负责。
默认项每类各一个（游戏设置、模组、资源包、数据包），在预设管理里选中某一份后点「设为默认」
只影响它自己那一类；混在别的类里那一份不会被换下来。旧版本那个唯一的默认项照旧读、照旧写回，
但不自动迁移成四类组合：它只在自己那一类还没表过态时顶上来，别的类不会被它点亮；它若是旧版
混合预设（没有类别），一类都不推导 —— 不静默重组混合默认。默认项被删掉或读不回来时，那一类
就是没有默认（不偷偷换成同类的下一份），安装页对应那一栏回到「不使用」。
安装页记住的是"用户亲手改过这一栏"：没动过的那一类，以后设了默认会自动选上；亲手改成
「不使用」的那一类，不会被后来的默认再顶上来。
管理列表支持按名称或说明搜索；清空搜索恢复列表。从实例提取默认折叠，展开后仅展示当前类别
允许提取的选项。“更新当前预设”替换对应内容，“提取为新预设”保留当前这一份。

## 模组执行保护

### 已安装模组与依赖

预设安装先在后台扫描当前 `mods` 顶层的启用 JAR，不遍历其它目录；禁用文件不满足启用依赖。
已有识别缓存、安装记录都要与当前文件 SHA-1 对上，不能凭文件名或只凭缓存时间认版本；
也会用本次平台答复中的文件哈希确认改过名字的文件。项目、发行版和依赖元数据分别判定，
重复项目或精确版本冲突不会自动覆盖。已安装父模组仍展开自身的必要前置，只补缺失项。

写入前后台重核一次文件清单；增删或内容变化会中止并要求刷新。失败、取消保留旧身份记录。
实例目录被外部删除时不重新创建；执行器销毁会取消后台扫描。可选项身份未确认只记为可选失败，
不阻止已确认安全的必要项；同一内容对应多个项目/发行版时不采用先返回的那个答案。
扫描限 10000 个 JAR、每 1 MiB 检查取消，整项仍有 600 秒预算。
未确认的文件继续通过 Modrinth `POST /version_files` 查询实际 SHA-1 对应的发行版，
每批最多 100 个哈希、顺序去重查询，沿用整项 600 秒预算；不使用查询最新更新的接口。
响应必须包含匹配的文件哈希、项目及发行版身份，再检查目标游戏版本、加载器与精确依赖。
已确认的其它平台身份不被 Modrinth 答复覆盖；已有 Modrinth 记录与答复冲突时拒绝自动改写。
这不是全盘识别：无结果、限流、损坏响应和取消都不证明文件不存在，仍说明身份未知。
其它平台的已安装文件哈希/指纹反查仍待接入；这与“只有平台发行版ID的前置反查”是两件事。
缺失项目可以在下载前确认页明确填写本次替代，重新检查替代项目和全部必要前置后再次确认。
未知状态不能靠填写替代静默放行；已有冲突文件也不自动覆盖。

- 复用资源平台取数与生产下载器；顺序查询并去重，必要前置最多 256 个项目，整项最长 600 秒。
- 平台明确没有发行版与网络未知分开；必要项未解决时不写入模组。
- Modrinth 必要前置只有发行版 ID 时，先通过官方 `GET /version/{id}` 确认项目身份，
  再按原有游戏版本、加载器、文件哈希和精确约束检查；不以最新版替代指定发行版。
  单次操作去重发行版查询，最多 256 个，沿用网络超时及整项 600 秒取消预算；
  响应身份不符、字段缺失或查询失败仍显示原因，不写入依赖未确认的模组。
  CurseForge 仅文件ID的前置也已接入批量文件反查，必须返回唯一、匹配的文件ID及所属项目；
  错误身份、鉴权失败和损坏响应都不能满足前置。不代表全量已安装文件的平台反查已完成。
- 必要文件全部通过大小/SHA-1 检查后才进入写入阶段；不接受无可信 SHA-1 的远端模组。
- 文件名只接受安全 JAR 基名，拒绝路径穿越、危险目录链接和同名内容冲突；已有文件不覆盖。
- 可选依赖失败时保守跳过可选下载项，不留下已知缺前置的可选模组。
- 精确依赖按平台发行列表里的版本 ID 筛选；互斥约束和缺少项目 ID 的版本专属依赖安全阻止。
  安装计划层也执行精确约束合并：不同父项钉住同一前置的不同发行版时汇总冲突；只有发行版 ID
  没有项目 ID 的必要前置显示“暂无法确认”。`installedKeys` 仅证明项目存在，精确约束还须
  `installedVersionIds` 提供平台发行版 ID；未知或不匹配不得视作满足。此输入契约不代表已完成
  全实例文件的平台身份取数，也不提供静默替换。
  共用计划层合并多父项精确版本约束，在原候选集合里选择匹配发行版；冲突汇总，
  有效循环去重，不能收敛的约束明确阻止。可选前置只列出、不自动加入；必要前置失败会沿父项传播，
  不牵连其它独立的可选分支。没有身份的已安装文件不能被当作满足前置。
  中途写盘错误会如实报告已写入数量，不声称全量回滚。
- 执行记录原子保存到实例的 `wtfml.preset-mod-install.json`，包含版本/加载器、所选预设内容快照、
  计划文件身份、成功/取消/部分失败状态；`plannedFiles` 只是计划，不代表每项均已落盘。

## 查询、确认与恢复（2.2.1–2.2.3）

预检查先做本地判定，再查进程内缓存和平台；最多4项在途、单项12秒、整轮最多600秒。
新一代查询、单项/整轮超时、取消和对象销毁都会真正取消请求及后续退避，不只丢弃回调。
缓存按平台/项目、游戏、加载器、运行侧、发布筛选、数据版本、接口根和凭据摘要区分；
只缓存明确匹配/缺失，格式损坏、元数据缺失和未取完分页均为暂无法确认。
CurseForge 预检查与资源页沿用同一来源设置：有自有key走官方，否则可用配置的公共镜像。

最终确认列出具体发行版、文件、大小、前置、冲突和替代差异。替代仅本次有效，不改写预设；
拒绝/关闭会取消，必要项未解决不能进入下载。跨预设引用去重后只执行本次实际选择，
下载前和部署前重新核对所选预设内容及目标；内容变化要求重新预览。

同一实例的预设应用持有专用写锁。必要下载先全部校验，再依前置优先顺序部署；
每个文件原子提交，文件之间让出界面并可取消，已提交项保留，不宣称整趟回滚。
模组报告逐项区分 planned/downloaded/enabled/skipped/blocked，并记录原项目→本次替代项目；
下载前、部署前、每个文件提交后及终态都原子保存。写报告失败会停止后续部署。

设置等本地预设报告保存为实例内 `wtfml.preset-apply.json`：计划完成且覆盖获确认后才建报告/备份，
记录各段实际写入、移除、失败和待应用数量；options及资源包启用不把尚在内存中的计划当作已完成。
预设页提供“执行报告”和“继续未完成”，后者需再次点击确认；重启后仍可用。
本地段恢复校验实例根、预设指纹和逐项状态，只重试未完成段；模组恢复重新核对完整选择与实际SHA-1，
已确认落盘项不重复下载。源预设改变、损坏/不匹配报告不能自动恢复。
没有世界的数据包明确为 pending-world，继续时重新检查目标世界；不创建世界、不冒充已启用。
部分应用不新增启动门禁，但会明确警告并保留实例、已写入项和备份。当前报告是每实例最近一次，非完整历史中心。

## 模组管理按钮原设计

原稿在仓库上一级 `其余的一些设计.md` 的「Mod 操作 / 批量操作规则」：
选中模组出现 Action Panel；包括启用、禁用、更新、删除、打开目录、详情、配置管理。
混合选择启用/禁用模组时，按原稿隐藏启用/禁用，仅保留无歧义的批量操作。
本轮只定位并记录此计划，未擅自修改模组管理页面的布局。

2026-10-18 用户补充示意图：采用「实例导航 / 宽模组列表 / 窄操作栏」版型，
左侧沿用现有实例导航，不照搬示意图。右侧建议宽 240–280 逻辑像素，不反向撑高/撑宽窗口；
无选择时收起或显示简短提示，清除选择与关闭操作栏的行为应明确区分。
列表上方保留添加、搜索/排序、全部/已启用/已禁用/需要处理及全选/反选/清除。
选中行保持主题浅底，行内显示名称、版本、实际启用状态和有依据的兼容/问题标记，
未知不能伪装成兼容。右栏按状态控制、版本管理、实例迁移、删除、更多分组。
同日补充原始对话后，以原稿后段为准，旧 MD 的“混合选择隐藏状态操作”已过时：

- 未选择时面板收起；选中后从右侧滑入，不做遮挡列表的悬浮菜单，也不全局常驻。
- 固定位置的状态下拉提供「全部启用 / 全部禁用 / 逐项反转」；反转明确指每项独立翻转，
  不是按第一项状态决定整批动作。操作前展示已启用/已禁用数量。
- 全选/反选/清除属于列表顶部的选择工具，不放右栏。
- 高频主操作为状态、检查更新、复制到实例、删除；实际更新放后续确认，移动比复制有更高风险。
- 标题显示已选择数量；成功后收起、失败保留是对话中的建议，具体是否清空选择仍应结合操作定义。
- 更多容纳详情、文件位置、依赖/冲突、网页、导出列表；只在有能力时显示，不把未知伪装成检查成功。
- 删除需确认；“同时删除配置”仅是原稿建议，默认不勾选，配置归属不明确时不提供破坏性操作。
- 固定面板、自动整理/清残留、测试实例/启动验证属于助手提出的扩展建议，并非已确认首版要求。
- 共用可选 `ContextActionPanel` 容器，但不强制所有页面三栏化；存档、服务器、资源包未来按需接入。

用户随后已接受交互修正：保留成功后的选择、× 仅收起、清除选择放列表顶部、反转移入更多、
删除不附带清配置。最终实现以 [MOD_ACTION_PANEL.md](MOD_ACTION_PANEL.md) 为准，上面的对话整理保留作历史来源。
