# 人工恢复目录：用旧目录替换当前目录

本文档说明实例还原或升级异常中断后，如何通过「用旧目录替换当前目录」进行人工安全恢复，供排查数据恢复与事务处理的开发者和测试员参考。

---

## 1. 适用场景与工作机制

在「设置 / 实例设置 → 备份 → 检查中断恢复」中选中一条待处理的还原事务时，若满足记录结构完好、源旧目录存在且目标路径合规，界面将显示「用旧目录替换（两份都保留）」按钮。

该流程遵循与自动还原一致的事务模型：

1. **登记可回滚事务**：动盘前将记录写为 `prepared` 状态，存入 `cache/restore-transactions/`。若后续重命名过程意外中断，启动器在下一次启动时会自动将当前目录复位至原始位置。
2. **运行状态前置检查**：若游戏处于运行中、实例正被安装/复制/备份/还原操作占用，或另一启动器进程持有数据目录会话锁，操作直接拒绝执行。在用户点击确认对话框的前后均执行该检查。
3. **数据双向保留**：被替换下来的当前目录重命名至同级 `.wtfml-restore-previous-<uuid>`，不执行删除；事务状态更新为 `published` 保留在 `cache/restore-transactions/`，在「中断恢复检查」中保持可见。人工核对确认后，可点击「保留两份，标记已检查」将日志归档到 `cache/restore-reviewed/`。
4. **暂存隔离保护**：恢复逻辑仅处理当前事务明确涉及的目录，不递归删除未登记的暂存目录，不修改 `OwnedStaging` 管理的目录。

---

## 2. 边界约束

- **同级同父路径约束**：源目录与目标目录必须位于当前游戏目录内、且处于**同一个父目录下**；路径中禁止包含符号链接（symlink）或目录联接（junction）；目标禁止指向启动器内部的 `.wtfml-*` 或 `cache/` 目录。
- **单目标单一记录**：单个目标路径仅允许维护**一条**恢复记录。若用户选择的旧目录恰好是某条待处理记录的 `retained`，则原地改写该记录（将新 `retained` 指向刚替换下来的目录），不创建并发记录，防止多条记录在恢复时产生时序冲突。
- **记录冲突防护**：旧目录若已被另一条指向不同目标的记录占用，操作拒绝；目标目录已存在其他不匹配记录时，需先处理既有记录。
- **目标不存在的简易路径**：若目标目录在磁盘上已不存在，旧目录直接改名复位至目标路径；启动恢复时无需保留待检查记录。
- **粒度说明**：本操作为**目录级**原子替换，不跨目录合并单项文件。

---

## 3. 验证工程

核心逻辑在 `tests/core_modules/BackupTests.cpp` 的 ZQ12 单元中验证（归属 `verify_instances`）：

- 替换目录后当前路径呈现旧版本内容，原目录作为 `.wtfml-restore-previous-<uuid>` 保留；
- 游戏运行中、文件占用或存在第二进程锁时，严格保持磁盘原样；
- 路径越界、跨父目录、记录冲突或不匹配时拒绝动盘；
- 验证单目标单记录改写逻辑与未登记暂存保护；
- 两次改名之间模拟异常中断，验证启动恢复正确回滚当前目录。

运行验证命令：

```powershell
ctest --test-dir build/verification-mingw13 -R '^wtfml.core-instances$' --output-on-failure
```
