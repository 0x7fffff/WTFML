# WTFML 新建实例：预设选择弹窗设计规范

> 文档类型：产品需求与 UI 交互设计  
> 适用流程：下载 / 安装 Minecraft 新版本 → 选择预设  
> 状态：设计方案，待开发评审  
> 原则：本弹窗只负责选择本次安装要应用的预设，不负责创建或编辑预设。

---

## 1. 功能定位

用户在安装新游戏实例时，可以选择已有预设，将其中的游戏设置、模组、资源包、数据包、光影包等内容应用到新实例。

预设与实例属于同一类管理对象：

- 用户可以在「管理 → 预设」中创建、编辑和管理预设。
- 用户可以从现有实例的维护页面，将受支持的内容另存为预设。
- 本弹窗只读取已有预设，并确定本次安装需要应用哪些内容。
- 本次安装的选择不应反向修改预设本身。

第一版仅面向客户端游戏实例，服务端安装暂不接入预设。

## 2. 设计目标

1. 让用户快速找到需要的预设。
2. 支持按内容类别选择预设。
3. 支持综合预设的整体选择和局部应用。
4. 显示预设内容数量及兼容性检查结果。
5. 避免多个预设对同一类别产生不明确的覆盖关系。
6. 让用户确认最终应用内容，同时控制弹窗复杂度。

## 3. 弹窗整体布局

推荐结构：

**左侧分类导航 + 右侧预设卡片列表 + 底部应用摘要与操作区。**

不建议将所有预设混成一张长列表，也不建议为每个类别再套一层弹窗。

### 3.1 结构示意

```text
┌────────────────────────────────────────────────────────────────────┐
│  选择预设                                                     ×    │
│  选择本次安装需要应用的预设。不同类别可以分别选择。                   │
├────────────────┬───────────────────────────────────────────────────┤
│                │  模组预设                                         │
│  游戏设置      │  ┌────────────────────┐ ┌────────────────────┐    │
│  模组          │  │ ⚡ 性能优化         │ │ 🧱 建筑辅助         │    │
│  资源包        │  │ 18 个 Mod          │ │ 12 个 Mod          │    │
│  数据包        │  │ 匹配 16 · 缺失 2   │ │ 尚未检查           │    │
│  光影包        │  │              已选择│ │                    │    │
│                │  └────────────────────┘ └────────────────────┘    │
│  综合预设      │                                                   │
│                │  ☑ 显示综合预设                                   │
├────────────────┴───────────────────────────────────────────────────┤
│  本次应用                                                          │
│  游戏设置：未选择   模组：性能优化   资源包：未选择                 │
│  已选择 1 个类别 · 缺失 2 项                                       │
│                                           [取消] [确认选择]         │
└────────────────────────────────────────────────────────────────────┘
```

以上为结构示意，不限定具体像素尺寸。整体风格沿用 WTFML 现有实例管理页面的视觉语言。

### 3.2 顶部区域

显示：
- 标题：`选择预设`
- 简短说明：`选择本次安装需要应用的预设。`
- 关闭按钮。

目标 Minecraft 版本、加载器等信息如果已在安装页面提供，不必在此重复；兼容性检查所需信息由安装流程传入。

### 3.3 左侧分类导航

第一版包含：

1. 游戏设置
2. 模组
3. 资源包
4. 数据包
5. 光影包
6. 综合预设

左侧导航负责切换右侧列表，不负责直接选择预设。可在类别名称旁显示该类别可用预设数量。统计时应避免因综合预设在多个类别出现而重复计算同一份预设的总数。

### 3.4 右侧预设列表

使用卡片或紧凑列表展示当前类别的预设。每张卡片建议包含：

- 预设图标、名称。
- 预设类型标识。
- 内容数量。
- 兼容性状态。
- 当前是否已选中。

示例：

```text
┌────────────────────────────┐
│ ⚡ 性能优化                  │
│ 模组预设                    │
│ 18 个 Mod                  │
│ 匹配 16 · 缺失 2            │
│                         ✓  │
└────────────────────────────┘
```

卡片保持简洁。具体缺失 Mod、依赖冲突等内容放入兼容性详情，不在主列表展开几十条明细。

### 3.5 「显示综合预设」开关

在游戏设置、模组、资源包、数据包、光影包等单类别页面提供此开关。

- 默认建议开启，方便从单类别入口选择综合预设中的对应部分。
- 关闭后，右侧只显示该类别的单一类别预设。
- 开关只影响候选列表显示，不改变应用规则。
- 综合预设仍在「综合预设」独立分类中显示。

是否记住用户上次的开关状态，可作为后续体验优化；第一版可使用固定默认值。

## 4. 预设类型与列表规则

预设按有效内容类别分类。综合预设是多个类别内容的合集，不是把多个独立预设复制拼接成临时对象。

| 类别 | 内容范围 |
|---|---|
| 游戏设置 | 游戏选项、原版按键等受支持设置 |
| 模组 | 模组清单及对应版本信息 |
| 资源包 | 资源包文件及其启用顺序 |
| 数据包 | 受支持的数据包内容 |
| 光影包 | 光影包文件及相关内容 |
| 综合预设 | 同时包含多个类别的预设合集 |

明确不纳入本轮范围：

- Mod 配置文件。
- Mod 专有按键或 Mod 专有设置。
- 服务端安装预设。

### 4.1 综合预设在不同入口中的显示

同一份综合预设可以出现在：
- 综合预设分类。
- 它实际包含的各个类别列表中（需开启「显示综合预设」）。

这些入口必须指向同一份预设数据，不得复制出多份独立预设。

### 4.2 从单类别入口选择综合预设

已明确的核心规则：

- 在「模组」分类选择综合预设，只应用其中的模组部分。
- 在「游戏设置」分类选择综合预设，只应用其中的游戏设置部分。
- 在「资源包」分类选择综合预设，只应用其中的资源包部分。
- 其他类别同理。

从单类别列表选择综合预设，不应意外应用其其他类别内容。

### 4.3 从综合预设入口选择

选择综合预设后，允许用户决定本次要应用其中哪些部分。

```text
日常生存
综合预设

本次应用内容：

☑ 游戏设置       12 项
☑ 模组            24 个
☑ 资源包           3 个
☐ 数据包           2 个
☑ 光影包           1 个
□ 其他类别         无内容（置灰）
```

规则：

- 预设中有内容且处于有效状态的部分，默认勾选。
- 没有内容的部分置灰，不可选择。
- 本次取消勾选只影响本次安装，不修改预设。
- 预设作者在概览中停用的部分，不应被当作默认有效内容。
- 被作者停用的部分是否允许安装者在本次临时重新启用，尚需产品确认，见「待确认问题」。

## 5. 单类别选择与冲突规则

### 5.1 同一类别最多选择一份预设

同一类别本次安装只允许有一个最终来源。例如，不能同时将综合预设「日常生存」中的模组部分和单独的「建筑辅助」模组清单不加区分地合并。

### 5.2 选择新预设时的替换行为

推荐采用类别级替换：

- 用户在模组类别选择新的模组预设时，只替换当前最终模组来源。
- 综合预设中的游戏设置、资源包等其他类别来源保持不变。
- 替换前给出轻量提示，明确将被替换的是哪个类别。

提示示意：

```text
替换当前模组预设？

当前模组来自「日常生存」。
是否将模组部分替换为「建筑辅助」？

其他类别不受影响。

[取消] [替换模组部分]
```

替换只作用于本次安装选择，不修改原有预设内容。

### 5.3 最终来源摘要

底部摘要应始终反映每个类别的最终来源，而不只是显示用户最近点击的预设。

| 类别 | 最终来源 |
|---|---|
| 游戏设置 | 日常生存 |
| 模组 | 建筑辅助 |
| 资源包 | 未选择 |
| 数据包 | 未选择 |
| 光影包 | 日常生存 |

如果一个综合预设的多个部分仍然有效，可以在多个类别中显示同一个预设名称。

## 6. 兼容性信息

预设卡片应简洁显示兼容性状态。

| 状态 | 含义 |
|---|---|
| 已匹配 | 已找到可用于目标版本 / 加载器的对应内容 |
| 存在缺失 | 有部分内容没有找到匹配项 |
| 存在冲突 | 发现明确的版本、依赖或加载器冲突 |
| 未检查 | 尚未完成检查 |
| 检查失败 | 检查过程失败，无法给出可靠结果 |

注意：

- 「未发现问题」不等于「已确认兼容」。
- 不得只根据文件名就将 Mod 标记为兼容。
- 应结合目标 Minecraft 版本、加载器、Mod 元数据、依赖关系及可获取的版本信息。
- 无法确认的项目应明确显示为未知或待检查。

### 6.1 兼容性详情

点击卡片中的兼容性状态或详情入口，可打开独立详情窗口。详情可包含：

- 已匹配项目。
- 存在更新版本的项目。
- 未找到匹配版本的项目。
- 加载器不匹配项目。
- 缺少依赖的项目。
- 无法确认兼容性的项目。

主弹窗不应直接展开大量明细。

## 7. 检查时机与性能

预设数量较多、单个预设内容较多时，不应在弹窗打开时同步扫描所有预设的所有文件。

推荐策略：

1. 弹窗打开时，优先读取预设元数据和已缓存的检查结果。
2. 先显示预设名称、类别、内容数量等轻量信息。
3. 对未检查或缓存失效的预设，在后台执行必要检查。
4. 用户选择某个预设后，再执行与本次目标版本和加载器相关的深入检查。
5. 目标 Minecraft 版本或加载器改变后，相关检查结果应失效或重新验证。
6. 检查期间界面保持可操作，避免整个弹窗卡住。
7. 允许逐项显示检查进度和失败状态。

检查结果可以缓存，但缓存必须关联目标版本、加载器及预设内容版本，不能把旧目标版本的结果直接用于新目标版本。

## 8. 资源包顺序与现有内容保护

资源包预设必须保存资源包顺序，应用时不能只复制文件而丢失启用顺序。

应用规则：

- 按预设保存的顺序处理预设涉及的资源包。
- 只处理预设明确涉及的资源包。
- 不应因为应用预设而无故删除用户现有、且未被预设涉及的资源包。
- 如果预设中的资源包与现有内容重名或冲突，应在应用前明确提示。
- 最终顺序应在安装预览中可核对。

若目标实例尚无资源包，则按预设顺序创建；若目标实例已有其他来源的资源包，应遵循不破坏未涉及内容的原则。

## 9. 底部应用摘要与操作

底部区域固定显示，不随右侧列表滚动而消失。

建议包含：

- 已选择的类别数量。
- 各类别最终来源。
- 已发现的缺失或冲突数量。
- 取消按钮。
- 确认选择按钮。

示意：

```text
┌──────────────────────────────────────────────────────────────────┐
│ 本次应用                                                          │
│ 游戏设置：日常生存  ·  模组：建筑辅助  ·  资源包：未选择           │
│ 已选择 2 个类别 · 发现 2 个缺失项目                                │
│                                           [取消] [确认选择]       │
└──────────────────────────────────────────────────────────────────┘
```

按钮语义：

- **取消**：关闭弹窗，不改变预设，也不提交本次选择。
- **确认选择**：将本次预设选择结果交回实例安装流程。

不建议叫「立即应用」，因为弹窗负责选择；实际文件安装、下载、复制和设置写入应由后续实例创建流程执行。

### 9.1 确认后的安装流程

确认选择后，实例安装流程继续负责：

- 根据目标版本和加载器再次验证必要兼容性。
- 显示将安装、跳过或无法应用的内容。
- 处理文件下载与复制。
- 处理资源包顺序。
- 在失败时提供明确的错误和恢复信息。

预设选择弹窗不能替代后续安装前的必要检查。

## 10. 空状态与异常状态

### 10.1 当前类别没有预设

```text
还没有游戏设置预设

可以前往「管理 → 预设」创建预设，
也可以从已有实例中另存为预设。
```

不应显示空白卡片或虚构示例预设。

### 10.2 只有草稿，没有可用预设

草稿不能作为安装候选。若该类别只有草稿，应提示当前没有可应用的预设。

### 10.3 预设读取失败

显示预设名称（如果元数据可读）、失败原因和重试入口。不能静默忽略后让用户误以为预设已应用。

### 10.4 兼容性检查失败

保留预设选择，但明确显示检查失败。是否允许继续安装由后续风险策略决定，不应把检查失败自动等同于兼容。

### 10.5 预设在弹窗打开期间被修改或删除

提交前验证预设仍然存在且版本未发生未处理的变化。若内容已经改变，应刷新检查结果并提示用户确认。

## 11. 第一版范围

### 第一版应包含

- 左侧类别导航。
- 右侧预设卡片 / 列表。
- 游戏设置、模组、资源包、数据包、光影包、综合预设分类。
- 单类别页面显示综合预设的开关。
- 单类别入口选择综合预设时，只应用对应类别部分。
- 综合预设入口支持选择本次应用的类别部分。
- 同一类别最多选择一份预设。
- 类别级替换提示。
- 预设内容数量与兼容性状态。
- 后台检查和基本缓存。
- 底部最终来源摘要。
- 取消与确认选择。

### 第一版暂不包含

- 服务端预设。
- Mod 配置文件。
- Mod 专有按键和 Mod 专有设置。
- 多份同类别预设自动合并。
- 预设编辑功能（由管理 → 预设负责）。
- 在本弹窗中直接修改预设内容。
- 复杂的兼容性修复操作。

## 12. 验收标准

1. 弹窗采用左侧分类、右侧列表、底部摘要的结构。
2. 用户能在各类别中查看对应预设。
3. 单类别页面可控制是否显示综合预设。
4. 从单类别入口选择综合预设时，只应用对应类别部分。
5. 从综合预设入口选择时，可以勾选本次应用的有效内容类别。
6. 没有内容的类别置灰。
7. 本次选择不会修改预设作者保存的启用状态。
8. 同一类别最多存在一个最终来源。
9. 选择新预设替换同类别来源时，有清晰提示，且其他类别不受影响。
10. 底部摘要始终显示每个类别的最终来源。
11. 资源包顺序得到保留，未被预设涉及的现有资源包不会被无故删除。
12. 兼容性检查不会阻塞整个弹窗。
13. 草稿不会出现在安装候选列表。
14. 确认选择只提交安装配置，不在弹窗内直接执行文件迁移。

---

## 13. 待确认问题

1. **作者停用的类别能否被安装者重新启用？**  
   已确认作者停用的类别不属于预设默认有效内容；是否仍允许用户在本次安装中临时勾选，需最终决定。

2. **「显示综合预设」开关是否记忆用户上次选择？**  
   第一版可先使用默认开启，后续再决定是否持久化。

3. **缺失或冲突项目是否阻止确认选择？**  
   建议弹窗允许用户确认选择并把风险带入下一步，由安装流程决定哪些问题是阻断项。

4. **综合预设中的部分内容被单独替换后，摘要如何呈现？**  
   建议按类别分别显示最终来源；原综合预设仍保持不变。

5. **是否允许用户在确认前逐个排除某个 Mod 或资源包？**  
   第一版建议只做预设级选择，具体项目级处理放在后续兼容性 / 安装预览步骤，避免弹窗膨胀。

---

## 14. 设计结论

第一版采用轻量的预设选择弹窗：

- 左侧分类导航负责切换类别。
- 右侧卡片负责展示和选择预设。
- 综合预设支持整体入口和类别局部应用。
- 每个类别只保留一个最终来源。
- 底部摘要展示最终应用结果。
- 兼容性检查在后台进行，详细内容另开窗口。
- 预设本身的编辑和保存继续由「管理 → 预设」负责。

**核心边界：预设选择决定“本次安装使用什么”；预设管理决定“这份预设本身包含什么”。两者不能互相修改。**
