## 保留现有决定，避免反向重做

- 新页面默认创建副本；现有原地升级和手动回滚继续保留，不能因为规范把它写进未来扩展就删掉。
- 副本模式不额外强制生成整份 ZIP，来源本身保持不变；原地模式仍必须先完整快照并校验后替换。若用户另选额外快照，单独计入时间与空间。
- 平台适配文件和必要前置已经能下载并做摘要校验，沿用现有下载链路；未知/必要缺失仍须处理，不把新界面变成绕过检查的入口。
- 原型只画了加载器类型，生产选择必须包含具体加载器版本，校验游戏/加载器组合；旧版本列表不能复用到另一个目标。
- 第一版默认在来源所属游戏根创建独立新实例；跨根目录放置若要开放，须把两个根的锁、空间、路径和历史归属纳入计划，不能只改一个路径字符串。
- 第一版按类别迁移全部存档；逐世界、逐截图文件选择可后续扩展。保留旧快照材料和失败证据，不新增自动清理策略。
- Mod 配置是这项迁移设计的内容，不改变预设系统不收录 Mod 配置及专有按键的既定范围。

## 类别与路径

类别键与展示名分开；以已有 `TransferPlanner::Item::key` 为基础，新增键先定义再用于持久化。下表是待统一的映射，不是已接入的新执行协议。

| 展示类别 | 建议沿用的键 | 内容与约束 |
| --- | --- | --- |
| 游戏存档 | `saves` | 选中的有效用户目录下整个 `saves/`；世界内 `datapacks/` 随世界走，不再重复列项 |
| Mod 文件 | `mods` | 按逐文件保留/禁用/替换和前置计划处理，包括父 JAR 与嵌套内容的关系 |
| Mod 配置 | `config` | `config/` 与 `defaultconfigs/` 作为同一展示类别的子路径；未知归属不得按 JAR 文件名猜测 |
| 游戏设置 | `options` | `options.txt` 的已确认设置项；资源包启用列表与实际迁入文件共同决定，避免引用未迁入包 |
| 资源包 | `resourcepacks` | 文件、启用状态和优先顺序；不以能解压代替目标版本兼容 |
| 光影包 | `shaderpacks` | 文件与可确认归属的相关设置；渲染器缺失或兼容未知单独提示 |
| 截图 | `screenshots` | 普通文件，默认不选 |
| 原理图 | 待统一 | 现有 `structure` 仅对应 `structures/`；补 `schematics/`，按真实目录与文件类型去重，不混入 Replay |
| 服务器列表 | `servers` | `servers.dat` 与必要条目属性，复用现有读写保留策略 |

路径必须先通过现有隔离/共享目录规则解析，不能假定所有用户文件总在 `versions/<名字>/`。共享数据范围须在预览中说明；账户、令牌、启动器缓存、其它实例、日志和未知外部链接不随类别迁入。

## 页面与检查状态

1. 来源实例、游戏根和稳定身份来自进入页面时的上下文；返回仍回原入口，页面内选择不因切页丢失。
2. 控制器保存目标游戏版本、加载器类型/具体版本、名称和类别集合；扫描/报告附带代次及来源指纹。
3. 目标或影响计划的类别变化立即撤销旧请求、旧最终确认，过期回调不能改当前页面。
4. 兼容报告中的平台结果、本地声明、依赖与运行保证分开。无网络、检查失败、没有发行版和明确不支持不能合并为同一个状态。
5. 用户已确认的逐文件选择仅在同一有效上下文中保留；换目标后重新核对，不能沿用另一目标下的确认。
6. 预览按钮可进入检查结果；真正执行必须等待必要扫描、空间检查和阻断项处理完成。不能因为输入了名字就直接开始复制。
7. 主页面只保留操作所需名称、值、数量和状态；长依据进报告/确认处，不照抄原型的多处重复说明，不使用中点分隔文案。
8. 桌面目标为约 1000×750。窄窗和字体放大纵向重排，不能横向拖拽；底部动作保留，正文最后一项可完整滚到动作上方。

## 模组、配置与世界的风险处理

- 未识别模组先用现有内容指纹/本地声明核对，不按文件名或相似搜索替换；平台适配版和必要前置沿用当前执行前二次核对。
- 配置文件没有可靠的通用 Mod 归属表。能证明归属的按对应模组计划处理，其余列为归属不明，让用户明确选择复制或跳过；不能把整个 config 无条件当作已兼容。
- 取消 Mod 类别而保留配置类别时，需要处理这层依赖关系，不能隐式又下载模组，或悄悄取消用户勾选。
- 世界含有模组数据；复制成功不等于目标加载器/版本可安全打开。降级、跨加载器或关键模组缺失的风险在最终确认处显示，来源世界保持不变。
- 核心/必要模组/摘要校验等关键步骤失败沿用整笔不发布的保守语义。是否允许可选类别部分失败后发布，需要单独明确，不能从“报告支持部分失败”推导为允许发布半成品。

## 计划与执行边界

只读计划至少包含来源/目标身份及根、目标版本与加载器版本、类别键、逐文件来源/相对目标路径、操作类型、字节数、摘要/指纹、风险及用户选择。

扫描、兼容查询、空间核对和最终确认共享这份上下文。磁盘可用量只是预检，不是预留；保守预算包含所选内容、核心准备、替换下载和必要暂存。发布前重新核对来源与目标，不接受预览后新出现的同名实例。

副本执行复用：准备独立核心 → 准备选中内容的候选 → 应用已确认设置和模组替换 → 完整校验 → 发布 → 验证 → 记录终态。一个父任务贯穿全程，子阶段不新增一排任务。

取消只在既有安全点生效；提交/改名的短临界区不随意打断。相关实例占用与游戏根切换保护覆盖扫描完成到提交收尾，不能让后台结果写到用户刚切换的目录。

## 历史与恢复设计

- 复用现有事务 ID 和报告协议，扩充必要字段及读取兼容；不要平行创建另一份升级账本。
- 建议由游戏根内的事务/报告作为权威记录，记录来源和目标稳定身份，两边历史从同一事务检索。这样可以展示两边关系而不改写来源实例的普通文件。
- 若必须在两个实例各存一份索引，索引只引用同一权威事务；需要幂等补写与可见的待修复状态。记录失败不能只留下一个成功提示。
- 列表显示真实结果、类别、时间与前后版本；快照显示归属对象及版本，恢复前核对目标，不默认删除新实例。
- 成功/失败/取消/未处理按实际阶段记录。继续操作只重试计划允许的未完成部分，目标被外部改动就重新预览，不自动运行安装器。

对应主计划 U1–U8，先纯计划和 UI 样例，再接现有评估、事务与历史。新文件创建前查重，状态跟随页面/控制器的所有权，避免继续扩大 `InstanceSettingsDialog` 和 `MainWindow`。
