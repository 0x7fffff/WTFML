# 恢复响应性改进（2026-10-28）

## 本轮范围

先处理下载文件已补齐、用户再次点击“继续安装”时的文件校验。
原路径在界面线程逐项调用 DownloadCheckpoint::unchanged，可能读取整批大文件。

现在先启动原任务的校验阶段，将文件条目值交给后台作业；每个控制器最多一个校验作业。
恢复方法返回表示接受校验，并不表示校验/安装已完成。界面阶段提示明确显示“正在校验恢复文件”。
校验时只提供取消，不提供暂停；校验通过后回界面线程重新检查恢复条件，再调用原来的安装接续。

哈希保持完整 SHA-256/必要 SHA-1，不以大小或修改日期代替；按 1 MiB 读取并检查取消标记。
取消不会调用安装接续，明确取消后清理自身执行记录；关闭窗口/退出则保留记录供下次明确恢复。
后台只读取条目副本，不访问控制器/UI。控制器销毁使取消标记生效，已销毁对象不会收到完成回调。
原恢复记录的锁持续保留到校验收尾，不在后台校验过程中重写它。

恢复条件在后台作业结束后再次确认，拒绝期间启动其它操作造成的状态变化；原安装流程自身的
目标/预设指纹与提交保护继续生效。文件系统检查与实际提交仍有外部竞态，不能声称杜绝任意进程
在检查后的修改，也不保证失联硬盘的系统读取能立刻返回。

## 验证设计

新增独立 32 MiB 文件夹具，覆盖正常继续、取消、销毁、恢复条件撤回、外部文件修改，检查重复点击、任务能力、
原件保持和单次接续；打印提交校验请求的实际微秒耗时。已有跨真实进程恢复测试改为等待后台校验，
仍要求文件补齐后第二次明确点击才安装。

## 第五步：任务中心首次文件恢复与当前批次恢复（2026-10-29）

`DownloadBatchController::resume()` 的文件恢复分支现在复用单作业/代次/取消作业管理，
先持有恢复记录锁，在后台核对完整原件或已声明发行文件；界面明确显示“正在后台校验下载目标”。
核对期间禁止暂停与重复恢复，允许取消。回到界面线程后重查恢复条件、下载器忙态和原暂停批次身份，
再恢复原下载批次；原安装器仍负责当前流程的最终收尾，跨重启补齐文件不自动执行 Java。

后台同时返回已经完整计算的 SHA-256 指纹，交给下载器的私有已校验批次入口；
排队复用原始恢复条目，提交保护捕获已核对指纹，避免在排队和建立保护回调时再同步哈希同一原件。
提交时仍检查指纹，校验结束后发生外部改动不能覆盖。关闭控制器只取消校验并保留恢复记录；
明确取消当前暂停批次的校验，也终止下载器暂停状态，避免留下永久忙态。
公开的同步 resumeBatch/restoreBatch 兼容接口仍存在，任务中心生产接线不再调用它们；不能宣称所有低层接口均异步。
