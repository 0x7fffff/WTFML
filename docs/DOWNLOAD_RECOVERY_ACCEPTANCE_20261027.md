# 下载恢复接续验收（2026-10-27～28）

## 本轮实现

- 服务端文件批次在开始登记前绑定任务；保存原服务端、Java、版本、加载器及已解析下载清单。
  Paper 等动态构建不在继续时静默选择另一个构建。原元数据、EULA、属性、白名单与管理员文件
  改变时拒绝接续；下载期间再次检查，未获新确认不执行安装器。启动中的服务端阻止跨进程文件恢复。
- 预设暂存改为实例内 `.wtfml-preset-downloads/<sha1>.jar`，相同内容只下载一次。
  不自动删除暂存；旧文件每次仍须完整校验，不因文件名看似哈希就信任它。
  暂停保留实例忙态且停止计时；重新继续才恢复剩余执行预算，部署阶段不开放暂停。
- 任务中心接入独立模组预设任务，安装收尾只复用同一目标的活动安装任务，避免借用其它实例的进度。
  新进程补齐文件后等待明确继续；之后重新核对预设清单、游戏/加载器、目标模组文件并重新查平台元数据。
  必要项门禁、替代项本次确认及逐项报告沿用原规划器，不持久化 API key 或旧替代授权。
- 旧平台地址失效时保留暂存，用户再次继续才重新查询；不反复盲用失效 URL，也不自动部署。
- 外部移走实例目录时拒绝创建暂存，不重新建出已消失的实例。
