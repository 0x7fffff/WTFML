# 独立网络诊断程序使用说明

`WTFMLNetworkDiag.exe` 是 WTFML 的独立网络诊断工具，用于帮助测试员排查下载节点、网络协议、系统代理与加速环境的连通性与吞吐性能。该工具不修改游戏数据，每次测试在隔离子进程中运行，并在测试完成后自动清理临时文件。

---

## 1. 测试操作流程

1. **解压与启动**：将便携 ZIP 压缩包**完整解压**到任意本地目录，双击运行目录内的 `WTFMLNetworkDiag.exe`。
2. **基线测试（小文件）**：
   - 保持默认的“小 JSON”测试用例；
   - 保持勾选“明确直连 / 系统代理”以及两种协议（HTTP/1.1、HTTP/2 优先）；
   - 点击「开始对照测试」，观察不同线路与协议的握手及首字节延迟。
3. **大文件直连与分段对照**：
   - 切换测试用例为“大文件”；
   - 设置每组请求数 **1**、并发数 **4**，先不勾选“生产分段流程”，测试大文件基础吞吐；
   - 保持参数不变，勾选“生产分段流程”再运行一轮，观察分段并发对下载速率的提升及补段情况。
4. **指定代理测试**：
   - 若系统代理检测异常，可勾选“指定代理”，填写本地 HTTP 或 SOCKS5 代理地址（例如 `http://127.0.0.1:7897`）；
   - 地址仅填写协议、主机与端口，无需填写认证凭据。
5. **并发连接测试**：
   - 切换至“小 JSON”或自定义小文件地址，将重复请求数调整为 12 或 16，分别配置不同并发数进行测试，观察高并发连接下的连接稳定性。
6. **收集与提交结果**：
   - 测试完成后点击「打开结果目录」；
   - 将当次生成的 `network-日期-时间-编号` 文件夹打包压缩，反馈给开发人员；
   - 反馈时建议简要注明网络环境（宽带/Wi-Fi/移动热点）、代理软件工作模式（TUN/系统代理/规则分流）及节点地区。

---

## 2. 测试规则与参数限制

- **网络路由与代理**：
  - “明确直连”指示 Qt 禁用显式应用层代理设置；若系统启用了 TUN 虚拟网卡或网关分流，流量仍会经由该网络出口；
  - “系统代理”由底层自动读取操作系统配置的代理服务器；
  - “HTTP/1.1”强制使用 HTTP/1.1；“HTTP/2 优先”由客户端与服务器自适应协商，最终采用协议以实际报告中的 `protocol` 为准。
- **缓存与超时管理**：
  - 测试过程禁用本地 HTTP 响应缓存，每组任务使用全新临时路径；
  - 单组测试超时默认 120 秒（可在 5–180 秒范围内调节），整轮测试上限为 900 秒；
  - 点击停止或关闭窗口会终止当前子进程。
- **流量预算**：
  - 单组测试响应流量上限为 128 MiB，整轮测试上限为 512 MiB；当下载量达到上限时会自动停止测试。
- **隐私与凭据保护**：
  - 测试不会保存任何账号密码、Cookie 或私有凭据；
  - 日志中仅记录目标 URL 路径、证书链信息、DNS 解析地址与连接耗时。

## 3. 输出文件说明

测试结果保存在生成的专属结果目录中：

- `results.json`：每组测试的成功状态、限时、传输字节数、实际协商协议统计与首字节延迟中位数。
- `summary.csv`：测试指标的 CSV 表格汇总，方便对比各组表现。
- `case-XX/events.jsonl`：逐行 JSON 事件流，记录请求创建、TCP 握手、TLS 握手、重定向、响应头、每秒采样速率及重试决策。
- `case-XX/result.json`：单组用例的原始汇总数据。
- `case-XX/process.txt`：记录子进程标准错误日志，用于排查底层动态库或运行环境问题。

### 关键性能指标含义

- `request_ms`：从请求创建到传输结束的总耗时（含底层排队时间）。
- `first_byte_ms`：从发起请求到接收到首个响应正文字节的耗时；未获取到正文时为 -1。
- `lookup_ms`：传输完成后执行的独立 DNS 解析耗时。
- `sample.reported_bytes`：每秒采样的累计传输字节数。

## 4. 开发构建与自测

Windows 本机环境构建命令：

```powershell
# 编译网络诊断程序
.\tools\network_diag\build.ps1

# 打包便携式发布 ZIP（包含程序、Qt 运行库及本使用说明）
.\tools\network_diag\package.ps1

# 运行自动化单元测试（仅访问本机模拟服务，不消耗外网流量）
ctest --test-dir build/network-diag -R '^wtfml.network-diag$' --output-on-failure --timeout 40
```

## 5. 限流保护机制

当远端服务器返回 HTTP 429（Too Many Requests）时，诊断程序会在当前秒级采样点自动中止该用例，并将结果标记为 `throttled`。为避免继续对服务器造成过载压力，本轮针对同一目标主机的后续用例会自动标记为 `skipped`，其余不同主机的用例照常继续。如遇限流，请等待服务方限流窗口解除后再行测试。
