# 独立网络诊断程序

程序名：`WTFMLNetworkDiag.exe`。与启动器共用 `DownloadManager`、`ResumableDownload` 的源文件，
不启动主窗口、不读取账号、不安装游戏。每组新建子进程和临时下载目录，测试内容不执行，结束后自动清理，日志保留。

## 测试员怎么用

1. 将便携 ZIP **完整解压**，双击里面的 `WTFMLNetworkDiag.exe`，不要只复制 EXE。
2. 先用默认的“小 JSON”，保持“明确直连 / 系统代理”和两种协议勾选，点击“开始对照测试”。
3. 再选“大文件”，保持每组请求数 **1**、并发 **4**、不勾“生产分段流程”，测试同一文件的线路差异。
4. 保持其他条件不变，再勾“生产分段流程”跑一轮，观察分段是否改善大文件慢速、是否出现反复补段。
5. 如果系统代理结果不明确，可勾“指定代理”，填实际 HTTP 或 SOCKS5 地址，如 `http://127.0.0.1:7897`。
   不支持在地址中填代理用户名/密码，不要把其他人的代理端口照抄过去。
6. 最后可在“小 JSON”或自定义小文件上把重复请求数调到 12/16，分别用不同并发再测。
   **请求数只有 1 时，普通下载模式调高并发没有意义。** 重复同一文件测的是并发连接表现，不等于完整安装。
7. 点击“打开结果目录”，将本轮 `network-日期-时间-编号` 文件夹压缩后发回。

最好附一句：使用何种网络（宽带/Wi-Fi/热点等）、代理是否启用 TUN/规则/全局模式、所选出口是否相同。
不要在测试过程中切换代理节点；切换后应另开一轮。默认样例来自测试日志，不保证服务端永远保留，
样例 404 不等于网络故障；可以替换为已知有效的同一文件地址及 SHA-1/大小。

## 对照规则与边界

- “明确直连”是 Qt 不使用显式代理，**不能绕开 TUN、透明代理、网关或运营商路由**。
- “系统代理”由 Qt 对请求查询系统代理；日志记录查询前后和候选项。系统代理与指定代理可能最终走相同出口。
- “HTTP/1.1”禁用 HTTP/2；“HTTP/2 优先”允许协商 HTTP/2，服务器仍可退回 H1。以 `request_finished.protocol` 为准。
- 普通模式没有自动镜像替换：输入官方 URL 就测官方，输入镜像 URL 就测镜像，仍跟随其正常重定向。
  分段模式复用生产探测、分段、校验、补段及整文件回退；网络策略和记录器会传到内部下载器。
- 禁用 Qt 本地响应缓存，下载目标每组全新且不复用已有游戏文件；**不能清除操作系统 DNS 缓存或远端 CDN 缓存**。
- 每组默认 120 秒，可调 5–180 秒；主窗口另有独立硬超时（该值 + 3 秒），即使子进程卡死也能终止。
  整轮最多 900 秒。停止/关闭窗口会终止当前子进程，不取消启动器中的任务。
- 每组正文预算 128 MiB，整轮 512 MiB，以 Qt 回报字节计量，存在在途/缓冲误差，不含 HTTP/TLS 额外流量。
  多组大文件、重复请求或频繁重试可能用完预算；这类停止不应归类为网络故障。
- 不关闭证书校验。日志不记录 Cookie/Authorization，不保存 URL 查询值、片段、用户名或密码；
  仍会包含域名、URL 路径、文件路径、证书信息和 DNS 地址，分享前请检查。自定义 URL 的路径也可能含敏感信息。

## 返回的文件

- `results.json`：每组成功/失败、限时、字节数、实际协议统计、首字节中位数。
- `summary.csv`：同样指标的表格摘要。
- `case-XX/events.jsonl`：一行一条 JSON，含请求建立、连接开始、发出请求、TLS/ALPN/证书、
  重定向、允许列表中的响应头、首次正文、逐秒采样、错误及生产模块的重试/看门狗决策。
- `case-XX/result.json`：该组的原始摘要。异常杀死时可能没有，主目录仍保留不完整结果。
- `case-XX/process.txt`：如有子进程标准错误，脱敏后保存，用于排查启动/DLL/平台插件问题。

`socket_connect_start` / `request_sent` / `tls_encrypted` 是 Qt 实际发出的信号，不是抓包；
复用连接可能没有新的连接/TLS 信号，缺少这些信号不代表未连接或未加密。
`request_ms` 从请求创建计时，包含库内部排队，不等于纯服务器耗时。
`first_byte_ms` 指 Qt 首次向应用提供正文的时刻；没有正文的失败请求记为 -1。
`sample.reported_bytes` 是 Qt 的累计报告，可能更新不及时；`buffered_bytes` 是当时未读缓冲，不能简单相加。

DNS 在传输结束后额外查询，避免提前预热影响测试；`lookup_ms` 是**独立查询**耗时，候选 IP
不是该请求实际连接的 IP，代理也可能自行解析 DNS。当前工具不能单凭这些数据判定丢包、运营商限速或实际出口 IP。
正文内容不写入分享日志；校验结果和最终保存字节数用于区分网络成功与内容/磁盘失败。

## 开发构建与验证

Windows 本机 Qt 路径沿用项目环境：

```powershell
.\tools\network_diag\build.ps1
.\tools\network_diag\package.ps1
```

其他环境可自行用 CMake 指定 Qt 路径，开启 `WTFML_BUILD_NETWORK_DIAG` 并构建 `WTFMLNetworkDiag`。
构建脚本单次配置 180 秒、编译 600 秒上限。程序输出位于 `build/network-diag/tools/network_diag/`。

```powershell
ctest --test-dir build/network-diag -R '^wtfml.network-diag$' --output-on-failure --timeout 40
```

自测只使用本机 TCP 服务，不访问公网。覆盖普通下载、显式代理、重定向脱敏、实际协议记录、
软超时、父进程结束阻塞子进程、流量预算、SHA-1 失败，以及生产分段内部记录器传递。
它不模拟真实公网 TLS/代理出口质量，现场归因仍需测试员运行对照。

### 2026-10-18 限流保护更新

收到 HTTP 429 后，当前测试在下一次秒级采样时停止，并将结果标记为 `throttled`。
本轮同一入口主机的剩余项目标记 `skipped`，不继续向服务器施压；其它主机照常测试。
因此“限流后跳过”不是测速失败，也不能按零秒速度比较。再次测试前应等待限流解除，
不要通过反复点击开始来验证限流窗口。生产下载器与诊断共用节点复用和来源冷却逻辑。
