# 界面多语言（英文）

给要改界面文案的人：翻译文件在哪、怎么刷新、哪些字不翻、守卫怎么用。产品上的设置项见
[FEATURES.md](../FEATURES.md)「语言」。

## 现在是什么状态

- 源语言是中文：代码里的字面量就是简中界面，**zh_CN 不装翻译**。
- 英文是译文，放在 `assets/i18n/wtfml_en.ts`，构建时由 `lrelease` 生成
  `wtfml_en.qm` 并编进资源（`:/i18n/wtfml_en.qm`）。
- 已经翻的只有导航轨五项（主页 / 管理 / 下载 / 设置 / 智能体）和设置页「语言」那一行。
  其余界面的中文还没包 `tr()`，英文界面下仍显示中文 —— 那件事在 0.6.0 之后单独做
  （逐处包 `tr()`，守卫基线降到 0）。

## 运行期怎么选语言

`ui/UiLanguage.hpp` 是唯一出处：

- 设置键 `General/Language`，取值 `system` / `zh_CN` / `en`，默认 `system`。
- `resolve(设置值, QLocale::system().uiLanguages())` 是纯函数：显式档直接用；`system`
  时系统 UI 语言里有中文（含繁体）就 `zh_CN`，否则 `en`。认不出来的设置值按 `system`。
- `installTranslation()` 在 `src/main.cpp` 里、**任何界面创建之前**调用一次；`zh_CN` 什么
  都不做，`en` 装上面那份 .qm。资源里没有那一份时记一句警告、界面退回中文。
- 改了设置不即时生效：设置页弹提示，写「立即重启」和「稍后」。「立即重启」先放掉
  [目录会话锁](../features/DIRECTORY_SESSION_LOCK.md)、再起新进程（参数照抄本进程，
  `--acceptance-profile` 也在其中），最后旧进程退出。

## 构建对 lrelease 的要求

CMake 三种情况：

1. 有 Qt6LinguistTools → 用它的 `lrelease`；
2. 没有（静态 Qt 只编了 qtbase）→ 用 `-DWTFML_LRELEASE=<lrelease.exe 路径>`，不指的话
   自动在 Qt 安装前缀 `bin`、`QTDIR`、本机动态 Qt（`D:/Qt/Qt/6.10.1/mingw_64/bin`）里找；
3. 两个都找不到 → **配置阶段直接失败**。只有显式 `-DWTFML_I18N=OFF` 才允许跳过。

静态单文件版同样带英文：`.qm` 编进资源，不依赖外部文件。

## 改完文案之后

```powershell
pwsh tools/i18n-update.ps1                      # 用本机动态 Qt 的 lupdate 重扫 src/ 与 ui/
pwsh tools/i18n-update.ps1 -Lupdate <路径>      # 或者自己指
```

它会重写 `assets/i18n/wtfml_en.ts`：新条目是 `type="unfinished"`，已有译文保留。
**跑完打开 .ts 把新条目补上**——没翻的条目在英文界面里显示的是中文，构建不会因此失败。

要翻的写法（`lupdate` 认得）：

```cpp
tr("要翻的话")                                      // 类里有 Q_OBJECT 时
QCoreApplication::translate("MainWindowUI", "要翻的话")  // 不是 QObject 的界面层，上下文自己给
QT_TR_NOOP("要翻的话")                              // 只存不翻，用的时候再 translate
```

`ui/` 不许 include `src/`，所以界面层的类多半不是 `QObject`：那里一律用
`QCoreApplication::translate("上下文", "源文")`。

## 「这处不翻」怎么标

行尾写 `// i18n-ignore`：

```cpp
combo->addItem(QStringLiteral("简体中文"), QStringLiteral("zh_CN"));  // i18n-ignore
```

用途：日志与内部提示词、语言名的自称（「简体中文」「English」永远不翻）、只给开发者看的
字符串。整行都不计入守卫。

## 守卫

```powershell
pwsh tools/check-i18n.ps1              # 有文件比基线多就失败（CI 的 repo-rules 会跑）
pwsh tools/check-i18n.ps1 -UpdateBaseline   # 降基线时用（第 2 期逐目录降到 0）
pwsh tools/check-i18n.ps1 -SelfTest    # 验守卫自己那几条判据
```

判据：`src/` 与 `ui/` 的 `.cpp` / `.hpp` / `.h` 里，字符串字面量含汉字或全角标点、又不在
`tr(` / `translate(` / `QT_TR_NOOP(` 这类包装调用的括号里，就算一处。注释里的不算，
`#include` 后面的文件名不算，标了 `// i18n-ignore` 的行不算。基线是
`tools/i18n-baseline.txt`（`路径<TAB>处数`），当前 5230 处 / 270 个文件。

限制：按行扫，跨行的字符串字面量没有状态（本仓没用那种写法）；`QStringLiteral(QString(...))`
这种拼出来的串会被当成没包，宁可多报。

## 测试

- 测试一律钉 `zh_CN`：`tests/support/SettingsIsolation.hpp` 的 `requireIsolatedSettings()`
  在沙盒建好之后写 `General/Language=zh_CN`，所以每个用了这道守卫的入口都自动钉住。
  CI 的 Windows 是英文区域，不钉的话会让几千条中文断言一起变红。
  `tools/check-test-modules.ps1` 会检查这一句还在。
- 要验英文界面的用例自己装 `QTranslator`（见
  `tests/ui_check/modules/UiLanguageChecks.cpp`：`UiLanguage::loadEnglish()` → `installTranslator()`
  → 建一个 `MainWindowUI` 读导航文字 → 卸掉）。
- `ui_check` 那个 exe 通过 `wtfml_embed_translations(ui_check)` 带同一份 `.qm`。
- 真 exe 的取证走 `--acceptance-profile`：档案 JSON 里加 `"languageStep": "en"`，窗口起来
  之后会切到设置页、拍「语言」那一行、真改一次下拉框、拍提示卡、点「立即重启」；新进程带着
  同一个档案起来再拍一张。产物是 `settings-language-<pid>.png`、`language-prompt-<pid>.png`
  和两个 pid 的 `startup-<pid>.json`。

## 加了新语言时

1. `ui/UiLanguage.hpp` 加档位与 `resolve()` 的分支；
2. `assets/i18n/` 加 `<语言>.ts`，CMake 里把它加进 `FILES`；
3. 设置页那颗下拉框加一项（语言名用该语言自己的写法，标 `// i18n-ignore`）；
4. `ui/TitleBar.cpp` 的 `iconForLabel()` 加该语言下那五个导航文字。
