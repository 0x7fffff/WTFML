# 实例版本更新

入口在单个实例的「实例操作 → 版本升级」。当前实例始终是来源，不需要再选择来源目录。

## 操作

1. 打开独立的四步更新向导，第一步选择 Minecraft 版本、加载器及具体加载器版本。目标不再混入其它实例名称。
   稳定加载器版本作为默认建议；没有稳定版本时需要明确选择测试版，获取失败可以刷新。
2. 第二步检查模组表，在每一行选择「保留启用」或「禁用，保留文件」。本地声明符合默认保留，
   明确不支持默认禁用；未知、未检查必须明确选择，也可批量处理未确认项。平台查询可以停止，
   不把停止/失败说成没有适配版。刷新结果不覆盖用户的明确选择。
3. 第三步选择创建更新副本（默认，另起名字）或更新当前实例，并核对保留/禁用数量。两者保留全部普通用户文件。
4. 点击「开始更新」进入执行步骤。现有下载器自动准备独立命名的核心/加载器，完成后继续副本或原地更新，
   不再跳下载页、手动安装和重新挑选。核心准备可由任务中心取消，准备阶段有 900 秒看门狗；
   失败只留下可检查的准备目录，不修改原实例。关闭设置页会停止后续串联，不强行更新已关闭的页面。
5. 执行页显示任务阶段和最终结果。核心事务仍进行完整快照、校验及执行前确认；提问显示在向导内，
   不藏在被模态窗口禁用的主窗口里。文件事务执行中不允许关闭；核心准备可取消。
   创建副本目前先后台复制源实例，再对副本执行同一安全事务；
   中途失败或取消时已创建的副本不会自动删除。此保守流程占用更多磁盘，尚未优化成单次复制。
   准备目录名以 `wtfml-update-` 开头，可能作为安装器继承链的一部分，不自动清理。

只输入搜索文字、没有选择有效条目，或本地模组仍在读取/平台查询进行中/还有未确认项时，不能开始更新。
收起的下拉框不响应滚轮；模组列表独立滚动，不用整页嵌套滚动承载各步骤。

## 两种模组判断分开显示

- 平台：有目标发行版、未找到目标发行版、查询失败、元数据不足、身份未知。
- 本地文件：Minecraft 声明符合、不支持、明确排除目标版本、无法确定。

因此可以出现「平台未找到目标发行版；本地 Minecraft 声明符合」。这表示现有文件有声明依据，
不是强制跳过，也不是已经下载适配版。网络失败不能变成“没有适配版”。

已识别身份从现有识别缓存或预设安装记录读取，并与实际 JAR 的 SHA-1 核对；不会根据文件名猜项目。
每个页面使用独立的网络请求器，目标切换会取消旧查询，旧回调不能覆盖当前目标。
平台查询采用 Qt 异步网络并发，最多 4 路同时请求（无需为网络等待创建阻塞线程），有 180 秒总预算；
暂时失败最多重试一次，401/403/404/429 不反复重试。目标切换/停止会清除全部在途钥匙，旧结果不可回写。
CurseForge 查询失败后，可用已校验本地 JAR 的 SHA-1 向 Modrinth 核验文件身份，匹配后才查询后备项目；
不凭名称、slug 或相似搜索结果换平台，不自动改写原识别缓存。界面标注 Modrinth 后备；双边失败仍是未知。
2026-10-21 本机只读实测：默认 CurseForge 镜像对项目 547434 的 26.2/Fabric 请求返回 HTTP 503，
Modrinth 同项目请求返回 200。这证明当次镜像服务失败，不代表所有环境的所有失败均由同一原因引起。
失败的具体原因与项目 ID 写入启动器日志，不记录 API key。
结果更新保留列表滚动位置，可使用「重新检查」刷新本地文件和平台结果。
同时有平台目标发行版且本地声明符合的条目放在列表末尾的「正常兼容」分组，默认折叠；
失败、未知、无目标发行版或声明冲突仍优先展开显示。刷新保持用户展开状态，折叠不影响逐文件选择或计数。

## 本地声明的覆盖范围

- Fabric：`fabric.mod.json` 的 `depends.minecraft`，同时检查 `breaks.minecraft`。
- Forge / NeoForge：`META-INF/mods.toml` / `META-INF/neoforge.mods.toml` 的 Minecraft 必要依赖范围。
- 支持常见数字版本、比较运算、通配、tilde/caret、数组或关系和单个 Maven 区间。
  Fabric 单独按扩展语义版本解析，支持空预发布下界（如 `~26.2-`）、预发布比较及重复尾部通配符；
  不将 Maven 或 npm 的 caret 规则混入 Fabric。无法解析的范围、多个不同 Minecraft 范围仍保留未知。
- 声明通过一个子进程批量只读获取，每条最多 1 MiB、整批正文最多 16 MiB、最多 10000 个 JAR，
  整批子进程 60 秒超时；部分失败保留此前结果。平台身份核验另有 120 秒预算，声明失败不跳过已有身份。
  超预算部分明确显示未检查；嵌套 JAR、Quilt 和旧 Forge 注解声明尚未覆盖。

“Minecraft 声明符合”不等于运行保证：加载器具体版本、Java、必要前置、Mixin、组合冲突仍须进一步验证。
平台检查不自动替换文件；保留/禁用仍由用户确认，不提供完整依赖求解。

## 原地升级与回滚的数据保护（保留）

原地升级仅替换合并后的核心配置与客户端 JAR，不复制目标实例的存档、模组或配置。
新更新流程使用表格确认的逐文件保留清单；未列入清单的启用 JAR 默认禁用，不删除文件。
兼容旧调用入口仍会询问整体禁用或保持原状。操作前保存设置；替换完成后关闭旧设置页，防止旧控件回写。

准备和校验在后台运行，相关实例在任务完成前不能启动或修改。
任务中心显示准备、完整快照、快照验证、保留原目录、发布、校验和完成阶段。
快照包括实例内 assets、libraries 及全部普通用户文件，不沿用普通快照的排除规则；
先解压到独立临时目录，逐文件比较路径、大小与 SHA-1，原文件变化也会阻止发布。
符号链接、junction、不可读文件、空间不足或无法确认空间充足时拒绝升级，不静默忽略。
其它实例通过 inheritsFrom、jar 或目录链接引用当前核心时，也拒绝原地替换和手动回滚。
目录名就是原版版本号的共享基础实例不能直接原地升级，应先复制成自定义名称的独立实例。

快照验证成功后才移动原目录，发布或校验失败时尝试恢复；恢复也另行保留当前版本，不直接删除。
当前游戏目录中的恢复材料：

- `cache/backups/instances/`：升级前完整 ZIP，可由现有快照恢复入口使用。
- `cache/instance-upgrades/<事务编号>/journal.json`：持久化阶段记录，不要手动编辑。
- 同事务的 `original/`：可回滚的原目录。
- 同事务的 `replaced/`：回滚时保留的升级后目录，包括更新后的存档进度。

回滚不会合并存档进度，所需新进度可从 replaced 取回。启动时检查当前游戏目录中的未完成事务，
尝试恢复中断前的原实例；已成功提交的升级不自动回滚。恢复材料不自动清理。
改名、移动整个游戏目录后的事务重定位尚未实现，需使用完整 ZIP 快照恢复。
空间估算保守，准备副本、快照及校验临时目录可能需要数倍实例体积。
原地替换阶段仍不提供中途暂停/取消，大文件实机耗时待验收。
