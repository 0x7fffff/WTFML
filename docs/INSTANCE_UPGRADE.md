# 原地升级与回滚

实例设置 → 升级，选择**已安装**的目标版本：

- 「创建升级副本」继续使用勾选的迁移范围，原实例不变。
- 「完整快照并原地升级」不使用迁移勾选，保留原实例的全部用户文件和稳定身份，
  仅替换合并后的核心配置与客户端 jar。不会复制目标实例的存档、模组或配置。
- 游戏版本或加载器变化时，选择先禁用旧模组或保持原状。默认禁用只是安全措施，
  不代表已经检测出每个模组不兼容；本阶段不自动查找适配版本。
- 先保存设置再操作。替换后设置页关闭，防止旧控件把旧配置写回。

## 数据保护

准备和校验均在后台运行，相关实例在任务完成前不能启动或修改。
任务中心显示准备、完整快照、快照验证、保留原目录、发布、校验和完成阶段。

快照包括实例内 assets、libraries 及所有普通用户文件，不沿用普通快照的排除规则。
快照先解压到独立临时目录，逐文件比较路径、大小与 SHA-1；原文件变化也会阻止发布。
含符号链接、junction、不可读文件或无法确认空间充足时拒绝原地升级，不静默忽略。
其它实例通过 `inheritsFrom`、`jar` 或目录链接引用当前核心时，也拒绝原地替换和手动回滚；
这种共享基础版本请使用升级副本，不连带改变其它实例。
目录名就是原版版本号的共享基础实例也不能直接原地升级：后续安装器仍会按该版本号写入。
先复制成自定义名称的独立实例，再升级，避免重新安装旧版本时覆盖新核心。

快照验证成功后才移动原目录；发布或校验失败时尝试恢复原目录。
恢复也不删除当前版本，而是另外保留，发生故障时同时保住新旧两份。

当前游戏目录内的材料：

- `cache/backups/instances/`：升级前完整 ZIP 快照，可用于现有快照恢复。
- `cache/instance-upgrades/<事务编号>/journal.json`：持久化阶段记录。
- 同事务的 `original/`：仍可回滚的原目录。
- 同事务的 `replaced/`：回滚时保存的升级后目录，包括升级之后的新存档进度。

实例设置 → 升级 → 「回滚最近一次原地升级」，恢复最近一份保留原目录。
回滚不会合并存档进度；需要的新进度仍可从 `replaced/` 取回。
启动时会检查**当前游戏目录**的未完成事务，尝试恢复中断前的原实例，并写入日志。
已经提交成功的升级不会在启动时自动回滚。

不要手动编辑事务日志。恢复材料不自动清理；删除前应自行确认不再需要回滚。
改名、移动整个游戏目录后的事务重定位尚未实现；这类情况应使用完整 ZIP 快照恢复。
空间估算采用保守余量，准备副本、快照和校验临时目录可能需要数倍实例体积。
当前阶段不提供中途暂停/取消按钮，大文件实机耗时仍需验收。
