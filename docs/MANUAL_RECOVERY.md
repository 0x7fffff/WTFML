# 人工恢复目录：把旧目录换回来

入口：「设置 / 实例设置 → 备份 → 检查中断恢复」里选中一条待检查的还原事务，点
「用旧目录换回来（两份都留着）」。只在这条记录读得懂、旧目录还在、目标目录要么是
目录要么已经不在了时才出现这一颗按钮。

## 它解决的问题

还原事务在「旧目录已挪走、新目录还没发布」之间被打断时，启动恢复能自己判断；但
**目标与旧目录同时存在**那种现场，到底要新的还是旧的只有人知道。以前只能自己到资源
管理器里改名，绕开了事务与运行状态检查。现在这一步和还原走同一个模子：

1. **先登记可回滚事务**：动盘之前把记录写成 `prepared`，放进
   `cache/restore-transactions/`。两段改名之间断掉时，启动恢复把「现在这一份」放回
   原位 —— 这一趟人工恢复等于没发生，挑中的旧目录原地不动。
2. **检查运行状态**：游戏在跑、实例正被复制 / 备份 / 还原 / 安装占用、或者另一份
   启动器占着数据目录时，一个字节都不动。界面先判一次，确认框（嵌套事件循环）之后
   再判一次。
3. **保留双方**：换下来的「现在这一份」改名到旁边的
   `.wtfml-restore-previous-<uuid>`，不删；记录改成 `published` 留在
   `cache/restore-transactions`，在「中断恢复检查」里继续可见，核对完再点
   「保留两份，标记已检查」把日志归档到 `cache/restore-reviewed`。
4. **不清理未知暂存**：换目录这一层一个递归删除都不做，也不碰 `OwnedStaging` 的
   任何目录；没登记的残骸照旧留给人工检查。

## 边界

- 两个目录必须都在当前游戏文件夹里、**同一个父目录下**、路径上没有符号链接或
  junction；目标不能是启动器自己的 `.wtfml-*` 或 `cache/` 底下的东西。
- 同一个目标只允许**一条**恢复记录。如果用户挑中的旧目录就是某条待处理记录的
  `retained`，这一层改写那一条（新的 `retained` 指向刚换下来的那一份），不再写第二条
  —— 两条记录都指向同一目标时，启动恢复谁先跑谁赢，结果取决于文件名排序。
- 旧目录被另一条记录认领（目标是别处）时拒绝；同一目标上有一条记录但记的不是用户
  挑的这一份时也拒绝，先处理那一条。
- 目标目录本来就不存在时，旧目录直接改名过去；没有「换下来的」那一份，记录在
  启动恢复时被收掉（没有旧目录可检查）。
- 这是一次**目录级**换位，不合并任何一方的文件；也不会替用户决定哪一份更新。

## 验证

`tests/core_modules/BackupTests.cpp` 的 ZQ12（`verify_instances`）：

- 换回旧目录、当前目录内容变成旧那一份、换下来的原样留在旁边；
- 运行中 / 占用 / 另一份启动器持有数据目录 ⇒ 不动盘；
- 越界、不同父目录、被另一条记录认领、与记录对不上 ⇒ 不动盘；
- 同一个目标只留一条记录、记录改写正确、未登记暂存一个字节没动；
- 两段改名之间断掉 ⇒ 启动恢复放回「现在这一份」；目标原本不存在的情形。

`ctest --test-dir build/verification-mingw13 -R '^wtfml.core-instances$' --output-on-failure`
