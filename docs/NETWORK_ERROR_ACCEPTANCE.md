# 网络错误验收（延后项）

> 状态：**未执行，延后**。
> 原因：本轮 G1A 人工审查没有条件安全地构造这些网络现场；不把它们写成已通过。
> 关联：[G1A 验收流程](G1A_ACCEPTANCE.md)、[Stage 1A 实现](AGENT_STAGE1A.md)、[Stage 1B 实现](AGENT_STAGE1B.md)。

## 1. 为什么不放进 G1A 结论

G1A 本轮人工审查已通过除网络错误外的项目。网络错误需要真实服务、代理、证书或可控本地服务器，
和“界面/凭据/会话”不是同一类现场；因此单独成一项延后，不阻塞 G1A 的其他结论。

## 2. 延后检查项

- [ ] 401/403：不自动重试，错误卡片提示检查 key/权限，能跳设置。
- [ ] 429：尊重 `Retry-After`（上限 60 秒），最多 2 次，显示等待；不无限重试。
- [ ] 断网（首字节前）：可重试 2 次，最终显示网络错误，不伪造成功。
- [ ] 流开始后断网：保留已收到内容，标“已中断”，不自动重发。
- [ ] 重定向 3xx：不跟随，显示协议错误；不把 key 发到新 host。
- [ ] TLS 证书错误：直接失败，不提供“继续”，不忽略证书。
- [ ] 系统代理：模型 API 遵循 Qt/系统代理；没有另建绕过路径。
- [ ] 400 等供应商错误：显示供应商 JSON 的安全摘要，不只显示“HTTP 400”。
- [ ] 错误卡片/日志/抓包中不出现 API Key、Authorization 头或请求 body 原文。

## 3. 建议的审查方式（以后做）

优先用本机可控服务，不消耗真实额度、不把 key 发到第三方：

1. 本机 loopback HTTP 兼容服务：设置页勾选“允许本地明文 HTTP”，分别返回 400/429/500/
   重定向/超时/断流。
2. 本地自签名 HTTPS 服务：验证证书错误直接失败。
3. 真实 provider：只测 401/403 和断网，不为了 429 刷额度。
4. 抓包：确认 URL 不含 key、key 只在认证头；抓包文件不提交、不入库。

## 4. 当前实现备注

- 流式请求收到非 2xx 时也保留供应商 JSON 错误体；错误卡片显示脱敏后的安全摘要。
- 网络错误分类：`Unauthorized`、`RateLimited`、`Quota`、`Network`、`Protocol`、
  `Cancelled`；401/403/配额不自动重试，首字节前网络/429/5xx 最多重试 2 次。
- 这条验收未完成前，不把网络错误矩阵写成“已通过”，也不影响 G1A 其他项的结论。
